# 09 · 发布：封面、平台文案、交付清单

**发布物料是这条活儿的一部分，不是事后补的。**
片子渲完只算完成一半——没有封面、没有标题、没有简介，它就没有被发布，只是存在于磁盘上。

```bash
node tools/build-covers.mjs      # 封面 → videos/<片名>/covers/*.png + covers.json
node tools/audit-covers.mjs      # 缩略图复核 → covers/cover-audit.json（有 finding 就 exit 1）
```

## 1. 一件已发布的成品需要什么

| 物料 | 具体是什么 | 落在哪 |
|---|---|---|
| 成片 | `renders/video.mp4`（本片 161.03 s · 1920×1080 · 30 fps · 60.1 MB · H.264 + AAC） | 渲染产物 |
| 封面 | 平台各自的比例，不是一张图裁四个尺寸 | `covers/cover-*.png` |
| 标题 | 每个平台一份，字数上限不同 | `PUBLISH.md` |
| 简介 / 正文 | 结论 + 数字 + **章节列表** + 素材署名 | `PUBLISH.md` |
| 标签 / 分区 | 平台命中用的关键词，不是自夸词 | `PUBLISH.md` |

**把这些写进一个 `PUBLISH.md`，和成片放在同一个目录。** 下一次谁要发，直接抄，不用重新想。

## 2. 封面从片子自己的设计系统长出来

不要另做一张"海报"。封面上那支麦穗**必须就是片子里那支**，字体**必须就是片子里那套**，
否则封面和成片是两个东西，观众点进来会觉得被骗。

真实做法：**headless Chrome 直接给独立 HTML 截图**。

```bash
chrome-headless-shell.exe \
  --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=1920,1080 --virtual-time-budget=4000 \
  --screenshot=<out.png> file:///<cover.html>
```

（可执行文件从渲染器自己的缓存里找：`%USERPROFILE%\.cache\hyperframes\chrome` 下递归找 `chrome-headless-shell.exe`；不要假设 PATH 里有一个 Chrome。）

四条设计决定：

- **字体 base64 内联。** 把片子的 6 个 woff2（`WheatDisplay` / `WheatSans` / `WheatSansRegular` / `WheatMono` / `WheatMonoBold` / `WheatSerif`）写成 `@font-face` + `data:font/woff2;base64,…`，带 `font-display:block`。**不内联，封面就会静默回落到系统字体**——尺寸全对、字全错，而且没人会发现。
- **图形构造器内联。** 内联片子的 `compositions/lib/wheat.js`，再调 `HF.ear({ h: 760, state: 'gold', grains: 7, glow: true })`：封面上的麦穗和片中的麦穗是同一段代码画的。
- **不挂进 `index.html`。** 封面是另一个画布尺寸；塞进片子要么拉长时长，要么污染时间轴。独立 HTML，独立截图。
- **先写到 ASCII 临时路径再截图。** 项目路径里含中日韩字符（`D:\...\视频工程\...`），`file://` + 非 ASCII 路径是毫无必要的失败源；写到 `%TEMP%/hf-covers/cover-<id>.html`，截完再 `copyFileSync` 回项目。

宽度高度**不要相信文件名**：从 PNG 的 IHDR 头读 `readUInt32BE(16)` / `readUInt32BE(20)` 与预期比对，不一致就 `exitCode = 1`。同时把 HTML 一起存进 `covers/`，出问题时能立刻改一版重截。

## 3. 比例与尺寸

| 文件 | 尺寸 | 比例 | 用途 |
|---|---|---|---|
| `cover-16x9.png` | 1920×1080 | 16:9 | 横版主封面（B站稿件封面 / YouTube） |
| `cover-bili-1146x717.png` | **1146×717** | 16:10 | **B站创作中心推荐尺寸——优先用这张** |
| `cover-4x3.png` | 1440×1080 | 4:3 | 信息流 / 推荐位 |
| `cover-3x4.png` | 1080×1440 | 3:4 | 抖音主页网格封面 |

**为什么 B 站要用 1146×717 而不是 1920×1080：** 这是平台创作中心自己给的推荐尺寸（16:10）。交一张 16:9 进去，它在网格瓦片里会被补边/压扁，你的构图留白全白留了。**平台给了推荐尺寸就用推荐尺寸。**

同一套设计、四种布局（`LAYOUT` 里每比例一组 `pad / num / title / hook / earH / earRight / vertical`，数字从 300 px 缩到 196 px，麦穗从 760 px 缩到 505 px）。**概念不动，排版重排。**

> **没做竖版就直说。** 本片只有横屏 16:9，`cover-3x4.png` 是**抖音主页网格**用的，**不是** 9:16 全屏竖版（1080×1920），也没有竖版重排版。说清楚"现在有什么、要不要我做竖的"，不要让人以为点开就是竖屏。

## 4. 在缩略图尺寸下审封面，不要在整尺寸下审

一张瓦片在信息流里**大约 240 px 宽**。所以决定性的问题不是"1920 px 下好看吗"，而是"**字缩到 240 px 还活着吗**"——整尺寸下看着很爽的细体小字，缩下去就是一团灰。

`audit-covers.mjs` 做六件事（阈值写死在脚本里，超了就 `exit 1`）：

| 检查 | 怎么量 | 阈值 |
|---|---|---|
| 尺寸正确 | 从 PNG IHDR 头读，不信文件名 | 尺寸比对在 `build-covers.mjs` 里做（不符即 `exit 1`）；`audit-covers.mjs` 只把它记进报告 |
| 不是一张黑图 | 全图平均亮度 | `meanLuma ≥ 4` |
| 文字区有墨 | 亮度 `L > 150` 的像素占比，取**左 62% / 上 68%** 区域 | `typeInkPct ≥ 1.2` |
| **缩略图下字还在** | 同一次测量，**把图缩到 240 px 宽再算一遍** | `thumbInkPct ≥ 1.0` |
| 麦穗还在 | 金色判定 `r > 78 && r > b+26 && g > b+8` 且 `L > 90`，取**右 30% / 下 78%** 区域 | `pictGoldPct ≥ 1.0` |
| 没被裁切 | 最外 **24 px** 边框内的亮像素 | `edgeInkPct ≤ 0.6` |

亮度用 `0.2126R + 0.7152G + 0.0722B`。整尺寸那一遍统一在 1920 px 宽上算，四张图才可比。

**真实结果（`covers/cover-audit.json`，`problems: []`）：**

| 文件 | `typeInkPct` | `thumbInkPct` @240px | `pictGoldPct` | `edgeInkPct` |
|---|---|---|---|---|
| `cover-16x9.png` | 5.21 | 4.46 | 6.36 | 0 |
| `cover-3x4.png` | 7.98 | 6.82 | 3.56 | 0 |
| `cover-4x3.png` | 5.77 | 5.22 | 5.18 | 0 |
| `cover-bili-1146x717.png` | 5.86 | 5.35 | 7.02 | 0 |

**字墨 5.2–8.0% 全尺寸、缩到 240 px 还剩 4.5–6.8%——字活着；四边 24 px 内 0% 亮墨——没被裁。** 注意 `thumbInkPct` 一定要单独看：它是"缩下去字会不会糊成一团"的唯一证据，和 `typeInkPct` 是两个不同的判据，别用一个代替另一个。

## 5. 平台文案：照这个标准写

### B站

- **标题上限 80 字，里面要有数字**（带具体数字的标题点击率通常更高——前提是内容真的撑得起那个数字）。
- **简介里放章节列表**：`00:00 …` 一行一个——平台会把它识别成进度条，**对完播有直接帮助**；收尾再给分区 + 标签。

真实交付（`videos/socrates-wheat-ear/PUBLISH.md`）：

```
推荐　苏格拉底的麦穗：37% 法则，算出你该在几岁停下来
备选　【最优停止】什么时候才算"遇到对的人"？数学的答案是 37%
备选　两千四百年前的麦穗，和一个能算出你人生转折点的公式
备选　37% 法则：先放弃三成七的人，你反而更容易选对
```

简介（节选，完整版见 `PUBLISH.md`）：

```
什么时候，才算"就是 ta 了"？
这个问题被问了两千四百年。而它其实是一个数学问题——最优停止（Optimal Stopping）。
结论很反直觉：前面 37% 的时间，你只看，不摘；之后遇到比之前都好的第一个，立刻下手。
这个策略把"选中唯一最好"的概率从 1% 提到 36.8%（n=100 时精确值是 37.1%，36.8% 是 1/e 的极限），
差了 37 倍。但即便算得这么准，你仍有 63% 的概率错过。
把它套到 18–28 岁：观察期在 21.7 岁结束，也就是大四。如果只看大学四年，那个点是 19.5 岁，大二上学期。

—— 章节 ——
00:00 一个躲不掉的问题
00:17 两千四百年前的那片麦田
00:42 他停下手，然后错过了
01:04 这就是爱情
01:16 这不是励志故事，是数学
01:38 前面 37%，只看不摘
01:46 36.8%
01:59 套到你自己身上
02:07 21.7 岁，大四
02:31 你不是在找最好的
02:37 落版
```

- **分区**：知识 → 科学科普（核心是概率与决策）；想走人文向则 人文历史。简介末尾署素材来源：`BGM：We Never — 世纪Official` / `字体：HarmonyOS Sans SC / Noto Serif SC / Consolas` / `制作：HyperFrames（HTML → 视频）· 全片无旁白，字幕即声音`。
- **标签**：`知识分享官` `数学` `科普` `概率论` `最优停止` `思维模型` `苏格拉底` `决策` `大学生` `恋爱`

### 抖音

- **标题上限 55 字，但前 15 字最关键**：把**问题**或者**数字**放最前面。
- 正文短：一句问题 + 一条结论 + 一次落到自己身上 + 一句来源声明。
- **话题标签 5–8 个**（给 10 个、按优先级从前往后取）。

```
推荐　什么时候才算遇到对的人？数学：先看 37%，再下手
备选　37% 法则：你该在几岁停止观望？
备选　苏格拉底的麦田里，藏着一条择偶公式
备选　21.7 岁，你的观察期就结束了

正文：
什么时候，才算"就是 ta 了"？
苏格拉底的麦田里，藏着一条 37% 法则：前 37% 只看不摘，之后遇到比之前都好的，立刻摘。
成功率 36.8%；随便选，只有 1%。
套到 18–28 岁：观察期在 21.7 岁结束，也就是大四。所以别问"还有没有更好的"，问你自己的标准到了没有。
（片中数字均为当场计算）

话题：#苏格拉底的麦穗 #37法则 #最优停止 #数学思维 #大学生 #恋爱观 #决策思维 #知识分享 #涨知识 #冷知识
```

发布建议里必须说清三件事：**前 3 秒已经是钩子**（本片 0.42 s 就打出的第一句字幕是「有个问题，你迟早得回答」，不需要为短视频再剪一版开头）；**16:9 在信息流里上下会留白**；以及**最狠的转化点在第 26 帧「21.7 岁」**，要做切片就从那里起。

## 6. 文案的两条诚实规则

**规则一：文案里每个数字都必须与片子对得上。**

本片有个真实的微妙处：片子显示 **36.8%**，那是 **1/e 的极限**；而 n=100 的**精确最优值是 37.1%**。所以简介里**两个都写**：

> 把"选中唯一最好"的概率从 1% 提到 36.8%（n=100 时精确值是 37.1%，36.8% 是 1/e 的极限）

**不许悄悄四舍五入成一个数。** 同理：片中每个数字都是脚本当场算的（穷举精确最优 + 20 万次固定种子蒙特卡洛），唯一的引用型数字（求职 +20%）带出处并标在画面上——这类事实要写进简介，它是可信度，不是注脚。

**规则二：不要承诺你没做的东西。**

只有横屏 16:9，就**不要**说"竖版已备好"。本片的正确说法是：`cover-3x4.png` 是抖音**主页网格**封面，原片 16:9 在信息流会留白，**要全屏竖版（9:16 1080×1920）需要另做——说一声就做**。说清有什么、缺什么、补做要什么代价，比含糊地让人点进来发现不对要强得多。

## 7. 交付前检查清单

| # | 检查 | 怎么验 |
|---|---|---|
| 1 | 封面文件都在，尺寸对 | `cover-16x9` 1920×1080 / `cover-bili-1146x717` 1146×717 / `cover-4x3` 1440×1080 / `cover-3x4` 1080×1440，**从 IHDR 头读** |
| 2 | 缩到 240 px 文字还活着 | `node tools/audit-covers.mjs`，`exit 0`，`covers/cover-audit.json` 的 `problems` 为空 |
| 3 | 标题在平台上限内 | B站 ≤ 80 字、抖音 ≤ 55 字；抖音**前 15 字**内有问题或数字 |
| 4 | 简介里的数字与片子一致 | 逐个对：36.8% / 37.1% / 1% / 63% / 21.7 岁 / 19.5 岁 / 37 倍 |
| 5 | 章节时间码与片子一致 | 对着 `audio/cue-map.json` 的帧起点，`00:00` 起、升序、覆盖全片 |
| 6 | 第三方素材许可齐全 | **BGM**（用户提供的原文件）、**音效**逐条在 `audio/sfx-licenses.json`（注明不是 CC0）、**字体**为子集（换机器要重跑 `build-fonts.mjs`，否则回落系统字体） |
| 7 | 分区/标签已填 | B站分区 + 10 个标签；抖音 5–8 个话题 |
| 8 | 封面用对的那张 | B站交 `cover-bili-1146x717.png`，不要交 16:9 |

**最后一句话：把全片最容易被记住的那个数字放进标题或封面。** 本片是 **21.7 岁**——它把一段两千四百年前的哲学和一条公式，落成了观众自己的年龄。标题里可以没有"苏格拉底"，但不能没有这个数字。
