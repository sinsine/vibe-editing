# 08 · 校验：凭什么相信这部片是对的

一部 33 帧、161 秒、无旁白（字幕即声音）的片子，靠肉眼审是审不完的，而且肉眼看不出
"每场景等 45 秒然后捕获静态帧"这种**全片死掉但零报错**的失败。所以校验被拆成**串行的闸门**：
每一道只回答一个问题，每道都有真实阈值，每道都写清它**证明不了**什么。

闸门按运行顺序排列。全部通过 ≠ 片子好看——见文末「这些闸门看不见什么」。

| # | 工具 | 看什么 | 关键阈值 | 真实结果（本片） |
|---|---|---|---|---|
| 1 | `tools/verify-frames.mjs` | 跨文件契约：id / 时长 / 字体 / 单位 / 模板 | 11 项断言，任一失败即 exit 1 | 33/33 帧 clean |

| 4 | `tools/frame-openings.mjs` | 开场姿态（t+60 ms 的字幕墨量） | 文字亮度过 150 luma 的像素 > 0.25% | 33/33 姿态正确 |

## 1. `tools/verify-frames.mjs` —— 跨文件契约（渲染前第一道）

lint/check 校验的是**单个文件**；真正毁掉渲染的失败几乎都是**跨文件**且静默的。这个脚本逐帧断言：

| 断言 | 阈值 / 检查方式 | 失败意味着 |
|---|---|---|
| id 三处一致 | 根 `data-composition-id` == 期望 `fNN`；`HF.register('<id>'` 存在；文件内不出现第二个不同 id | 运行时等 **45 s/场景**后捕获静态首帧：成片全长度、全死 |
| `data-duration` == storyboard 槽位 | 差值 ≤ **0.02 s** | 场景提前空白或拖尾 |
| `@font-face` 块数 | 恰好 **6** | 字体缺失，渲染回落到系统字体 |
| `<!--HF_FONTS-->` | 不许残留 | 字体注入没跑过 |
| `<head>` 里的 `<style>` | 不许出现 | 装载时被丢弃，画面变左上角无样式小字 |
| `<template>` | 必须存在 | 子合成必须是 templated 形状 |
| 两个库链接 | `../lib/<THEME>.css`、`../lib/<THEME>.js`、本地 `gsap.min.js` | 共享图形与动画运行时缺失 |
| `vw` / `vh` | 禁止（正则匹配 `\d+vw` / `\d+vh`） | 容器单位错，1px hairline 与版面全崩 |
| `Math.random()` / `Date.now()` | 禁止 | 渲染不确定，逐帧不可复现 |
| `crossorigin` | 禁止 | lint 报 `media_crossorigin_breaks_preview` |
| `.band-sub` | 必须存在 | 字幕不在保留带里，结构上无法保证"字幕不遮挡动画" |

**还有一条：未闭合的 `<title>`。** `<title>` 的内容模型是 RCDATA——一个丢掉 `</title>` 的标题会让
HTML 解析器把**整个 body 当成标题文本**，于是运行时"看不到根元素"，而磁盘上的标记**看起来完全正常**。
脚本专门找含 `<title>` 的那一行，要求同一行内 `</title>` 闭合（真实案例见 F11，用 `tools/fix-titles.mjs` 修复，
该脚本同时把标题规范成纯 ASCII，杜绝复发）。

**真实结果：33/33 帧通过。**（帧 1–11 没有 `accents/FNN.json`：这是对齐辅助，脚本报告但不判失败。）

它证明：文件层面与宿主能对上。它不证明：动画真的会动、版面真的不重叠、对比度真的够。

## 2. `npx hyperframes lint` 然后 `npx hyperframes check`

`lint` 是静态结构检查；`check` 开一个无头 Chrome 会话，跑运行时错误 / 版面 / 动效 / WCAG 对比度。
两者必须**分开看**，因为中间有一个陷阱：**一个 lint error 会关掉版面与对比度审计**。
此时 `check` 打印 `◇ 0 issues across 0 sample(s)` 和 `◇ 0/0 text checks pass WCAG AA`——
**这两行读起来像干净通过，实际是"什么都没跑"**。本仓库在真实运行中见过这个形态：
浏览器会话因为超时根本没起来时，同一份报告会打印
`⚠ Browser session never ran — layout, motion, and contrast below are empty placeholders, not a clean pass.`
然后版面/动效/对比度分别是 `0 issues across 0 sample(s)` / `0 errors` / `0/0 text checks pass`。

**判读规则：sample 数或 text check 数为 0，一律视为"未运行"，不是"通过"。** 先清 lint error，再信这些数字。

### 交付时记录的结果

`lint` **0 error / 1 warning**——warning 是 `composition_file_too_large`（生成的 `index.html` 361 行，
33 个槽位必然很长，属预期，不去"修"它）。
`check` 通过：运行时 0 错，对比度**终态通过**，只有 F05 入场错峰渐显期间有**一帧 2.9:1**（AA 要求 3:1）。

这一条怎么判：**一次刻意入场动画中途的瞬时低对比，是被记录的事实，不是需要"修掉"的缺陷。**
把它改到 3:1 就得把渐显改硬——用破坏设计去换一个只在 1/30 秒里存在的数字，是错的取舍。
判据是"瞬时且属于入场过程"，不是"数字不够大"。

### 本仓库当前工作树不再复现这份记录（重要）

`.hyperframes/artifacts/checks/` 里的落盘报告把这个结论说得很清楚，也很值得学：

| 报告 | lint | runtime | layout | contrast | browserSkipped |
|---|---|---|---|---|---|
| `1d173369…` / `82f6cb24…`（干净的那两次） | 0 err | 0 err | 0 err | ok | **false** |
| `6d57d845…` | 0 err | 0 err | 0 err | **1 warning**（2.9:1，t=28.825s） | false |
| `a4e49b74…`（只跑 F05 区间 26.2–29.2） | 0 err | 0 err | **4 err** | 1 warning | false |

后来对 `compositions/frames/05-rules.html` 的修改（mtime 晚于那次干净通过）让 F05 出现
`text_not_painted`（渐变文字用了透明填充，lint 判它"字看不见"）与 `container_overflow`；
把 `check --range 26.2,29.2 --at-transitions` 重跑在当前树上会得到 layout errors + contrast 1.1:1 / 2.9:1，
而**整片**（不带 `--range`）的 check 在当前环境下撞到自己的 deadline，
输出退化成"Browser session never ran"的空壳。

**结论怎么用**：引用 `check` 结论时要**绑定到那次运行的落盘报告和当时的输入**，
不要把它当成一个永久属性。改过任何一帧之后，"曾经通过"就失效了——得重跑才是当前状态。
30+ 场景的长片用默认采样数跑整片容易超时，**降采样**（`--samples 3`）或收窄
（`--range 26.2,29.2` / `--at 28.8`）即可，超时不是内容缺陷。
这也正是 §1 那道跨文件闸门存在的理由：它比浏览器闸门便宜得多，应当每次都跑。

## 3. `tools/verify-timing.mjs` —— 卡点，数据层 + 声学层

三条**数据断言**（容差 **15 ms**）：

| 断言 | 真实结果 |
|---|---|
| 每个镜头切点落在**小节线**上 | **33/33**，最差 **0.5 ms**（F05） |
| 每条字幕起点落在**拍线**上 | **41/41**，最差 **5.5 ms**（F11） |
| 每条音效 cue 落在**拍线**上（`bed` 类除外，共 3 条 bed） | **40/40**，最差 **1.7 ms**（"F1 尘埃落地 / 问号成形"） |

数据断言只证明"我想放的位置对"。它**证明不了成品里那条音效真的在那儿**——
混音 bug、limiter lookahead、被压到听不见的 cue 都会让数据通过而声音不在。

**声学层**因此做的是成品复核：解码渲染出的 SFX stem，把每条 cue 自己的**能量包络**（起音后 220 ms）
拿去和 stem 包络做**互相关**，在 **±80 ms** 内找最佳 lag。选包络互相关而不是音头检测，是因为
重叠 cue（whoosh 落在 impact 尾巴上）没有干净的 9 dB 上升沿，朴素 onset 会误判。

容差按**声音形状**给，不按同一把尺子：

| role | 容差 | 理由 |
|---|---|---|
| `hit` | **25 ms** | 打击类包络峰值尖锐，必须紧 |
| `whoosh` / `riser` | **80 ms** | 扫频/渐强包络宽而平滑，相关峰游走几十毫秒不代表声音动了 |

**真实结果**：40 条 cue 全部检出（`weakCorrelation = 0`），其中 **31 条被独立验证**，
误差**中位 2.7 ms**、均值 5.9 ms、最大 |err| 58.7 ms（F13 硬切森林的 whoosh，在它自己的 80 ms 容差内）。
小的恒定正偏移是 limiter lookahead，不是音乐漂移。

**诚实标注**：另有 **9 条**与另一条 cue 相距 < **350 ms**，两者的模板互相重叠，
包络互相关**无法把它们独立定位**。这些被标成 `ambiguous`，**不计入"通过"**——
一个边界大小的误差在这里是**歧义**，不是"错了"，但也不是"验过了"。

最终 `problems: []`，并写出 `audio/timing-verification.json` 供后续引用。

## 4. `tools/frame-openings.mjs` —— 开场姿态测试

要抓的失败：`fromTo` 在**构建时间轴的那一刻**就渲染它的 "from" 状态，所以同一个属性上有两对
`fromTo` 时，帧会**开场就持有后一步的状态**——可见症状是字幕（或任何后出现的元素）
在帧的最初几毫秒里已经在屏上，而它的第一条 cue 还没到。

测试是**经验性**的，不是静态检查：在每个 cut 之后 **60 ms** 抓一张静帧，测保留字幕带里的"墨量"，
若墨量超阈值而该帧第一条 cue 还没到期（允许 0.25 s slack），就标记该帧开场姿态错误。

**亮度阈值必须把文字和景物分开。** 字幕字形是纸白（约 **230 luma**），而麦田穿过同一条带时峰值约 **98 luma**。
一开始用 **60 luma** 作阈值，结果把 F10 的麦田报成了"提前出现的字幕"
（该帧开场带内 4.9% 像素亮过 60，但亮过 120 的是 **0.000%**）。
最终阈值定为 **150 luma**：只有真正文字亮度的像素才算字幕墨量；判定线是带的 **0.25%**。

**真实结果**：**33/33 帧开场姿态正确**。它证明开场第一态与 cue 表一致；
它不证明帧中段的每一拍都对（那是 §3 与音频复核的活）。

## 5. `tools/audit-still.mjs` —— 渲染静帧的像素体检

把 PNG 经 FFmpeg 解成原始 RGB（**480×270**，1080p 的 1/4，文件到文件、不走管道），
测那些"眼睛会抓到、linter 抓不到"的东西。阈值与判定：

| 指标 | 阈值 | 它抓的是什么 |
|---|---|---|
| `meanLuma` | < **1.2** 判失败 | 整帧基本全黑 |
| `litFrac`（luma > 12） | < **1.0%** 判失败 | 几乎没有被照亮 |
| `blownFrac`（luma > 250） | > **6%** 判失败 | 高光过曝 |
| `topLeftEdge`（左上 1/4×40% 的水平梯度均值） | > **6** 判失败 | **"CSS 从未生效"的指纹**：无样式内容全挤在左上角 |
| 字幕带墨量 `bandInk.subtitle`（luma > 60） | 与 `bandEdge.subtitle` 同时低于 **0.25% / 0.35** 才判失败 | 保留带里没有字幕 |
| 间隙带 `bandInk.gap`（luma > 60） | > **1.0%** 判失败 | 亮内容侵入 y842–872 |
| `goldFrac` / `goldCols[12]` | 无硬阈值，供人判读 | 金色重音是否真的落在该落的列上 |
| 分带 `bandEdge` / `bandInk` | 无硬阈值 | chrome / display / gap / subtitle / bottom 五带的墨与边缘密度 |

**本片被接受为设计意图的发现**（记录，不改设计）：

- **cue 间隙**：静帧取在 cut 后 60 ms 时，字幕尚未到期，字幕带自然是空的——
  `no detectable subtitle ink` 在这种采样时刻必然出现（§4 已从另一侧证明它是正确的）。
- **F04 的 `topLeftEdge ≈ 9.1`**：那条金色标题**按设计就在上方偏左**，不是无样式内容；
  该阈值是为"内容全挤在左上角"设计的，一个真正的版式会正常触发它。人工确认后接受。
- **F10 金色/麦田穿过间隙带**：`bandInk.gap ≈ 1.2–1.9%`，但那是**暗麦田剪影**，最大亮度约 **98 luma**——
  它证明间隙带的断言必须**只针对亮墨**，而不是针对边缘能量；暗的图形层穿过是没有问题的。

从成片回抽的 33 张中点帧上，这套审计只留下上面这两条（`topLeftEdge` 与 `gap ink`），其余全部干净。

## 6. `tools/audit-covers.mjs` —— 封面要按信息流里的大小验

封面不是在 1920 px 下被评判的：B 站网格瓦片大约 **240 px** 宽。所以决定性的测试是
"缩到 240 px 之后，字还认得出吗"——脚本每张封面解两次：全尺寸和 **240 px**，然后检查尺寸、
边缘是否被裁、字区是否有墨、缩小后字与底是否仍可分离、有没有字溢进图形区。

| 检查 | 阈值 | 真实结果（4 张：16:9 / 3:4 / 4:3 / B站 1146×717） |
|---|---|---|
| 尺寸 | 非黑，`meanLuma ≥ 4` | 24.7–27.3 |
| 字区墨量（左 62% / 上 68%） | ≥ **1.2%** | 5.21 / 7.98 / 5.77 / 5.86 |
| **240 px 复测**字区墨量 | ≥ **1.0%** | 4.46 / 6.82 / 5.22 / 5.35 |
| 图形区金色（右 30%、下 22% 起） | ≥ **1.0%** | 3.56–7.02 |
| **24 px 边缘保护带**内亮墨 | ≤ **0.6%** | 全部 **0** |

为什么必须有 240 px 那一遍：全尺寸下 1.2% 的墨量可以通过，缩到瓦片大小后笔画糊成一团，
字就"消失"了——而这一步在预览里看不出来，只有量出来才知道。`covers/cover-audit.json` 落盘，0 findings。

## 7. 渲染与渲染后复核

```bash
npx hyperframes render --quality delivery --output renders/video.mp4
```

渲染完成不等于交付。**要探测交付文件本身**：

```bash
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,sample_rate,channels,nb_frames \
  -show_entries format=duration,size -of default=noprint_wrappers=1 renders/video.mp4
ffmpeg -hide_banner -i renders/video.mp4 -filter_complex 'ebur128=framelog=quiet,volumedetect' -f null -
```

再从**成片**里抽帧，把 §5 的静帧审计跑在**成片的帧**上——这一步才是"文件确实等于设计"的证据，
而不是"合成在浏览器里看起来对"。本片抽的是每帧的时间中点（33 张），
逐像素统计与合成静帧一致（同 t 上比较，`boards/from-mp4/*.png` vs `boards/stills/*.png`）：

| t (s) | 成片 meanLuma | 合成静帧 meanLuma | 成片 gold% | 合成静帧 gold% |
|---|---|---|---|---|
| 3.60 | 13.94 | 14.94 | 1.555 | 1.556 |
| 21.67 | 29.07 | 30.16 | 7.070 | 7.208 |
| 49.30 | 17.52 | 19.47 | 1.529 | 1.593 |
| 62.06 | 17.57 | 18.58 | 2.013 | 2.147 |
| 110.95 | 18.11 | 21.43 | 2.295 | 2.299 |
| 159.36 | 14.44 | 15.39 | 0.426 | 0.381 |

金色占比一致到 **0.14 个百分点**以内；meanLuma 成片系统性略低（约 4–10%），
这是 H.264 + bt709 limited-range（16–235）编码的正常抬底/压顶，不是设计差异——
所以**静帧审计的阈值不能原样搬到成片上**，要比对的是"两边的统计是否同源"，不是"数值是否相等"。

| 交付指标 | 真实值 |
|---|---|
| 视频流 | H.264 (High) · **1920×1080** · **30 fps** · yuv420p tv/bt709 |
| 音频流 | AAC (LC) · **48 kHz 立体声** · 199 kb/s |
| 时长 / 大小 | **161.03 s**（161.033）· **60.1 MB**（62,971,204 B）· 3.13 Mb/s |
| 响度 / 峰值 | **−14.9 LUFS**（LRA 3.0 LU）· max_volume **−1.7 dB** |
| 帧数 / 渲染耗时 | **4831 帧** · **18 分 23 秒**（单卡 GPU；capture 18m12s / assemble 3.2s） |

响度与峰值这两个数来自混音阶段的 `tools/mix-soundtrack.mjs`（`ebur128` + `volumedetect`，
因为两者都往 stderr 输出，脚本用 `spawnSync` 而不是 `execFileSync`），
交付后再对**成片**复测一遍。混音器自己带闸门：时长偏差 ≤0.35 s、true peak ≤ −0.8 dBFS、
integrated loudness 在 −18…−11 LUFS 目标带内。

## 8. 这些闸门看不见什么（诚实说明）

- 它们证明**存在**（元素在、字体在、音频在）、**几何**（版面不重叠、保留带没被侵入、
  边缘没被裁）、**对比**（终态达 AA）、**时间**（切点/字幕/音效在网格上，成品音频里真的在那儿）、
  以及**字在缩小后仍然活着**。这五件事它们做得很好。
- 它们**不证明好看**，不证明**有品味**，也不证明**故事落地了**。
  没有一条断言能回答"这一帧是不是无聊""这个 cut 是不是太早""观众有没有被击中"。
- **均匀的网格不等于音乐性。** 33 个切点都落在小节线上，只能说明它们**不打架**；
  真正的节奏感来自帧与帧之间长度的对比（8.5 s 的麦田 vs 2.1 s 的一拍），那是编排决策，不是校验输出。
- **通过的闸门数量不是审片。** `33/33`、`0 error`、`0 findings` 描述的是"没有已知缺陷"，
  不是"已完成评审"。给人看的接触表（`npx hyperframes snapshot --at <midpoints>`）
  和人的判断仍然不可替代。

最后一条关于工具本身：本文件里的阈值、断言语义、失败模式都来自这些脚本的源码与它们产生的
`audio/timing-verification.json`、`covers/cover-audit.json`、`.hyperframes/artifacts/checks/*.json`。
引用它们时请引用**文件**，不要凭记忆引用数字——数字会随重跑而变，脚本行为才是契约。
