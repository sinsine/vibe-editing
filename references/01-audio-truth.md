# 01 · 音频真相：先测量，再写时间轴

这一篇解决一件事：**在你写第一行 HTML 之前，把音乐的拍点测出来**。产出是 `audio/hit-map.json` 和 `audio/timing-map.json`；后面排字幕、摆音效、切镜头、验收，全部只读这两个文件。

下文所有数字来自一部已完成的 161.017 s 成片（BGM 解码为 `audio/bgm-mono.wav`，22050 Hz 单声道）。**把方法搬走，不要照抄数字**——换一条轨，周期、相位、拍号、置信度都会变。命令按 `node tools/<script>.mjs` 写（本 skill 的脚本放在项目的 `tools/`，源工程同名同内容）。

## 0. 流水线三步

```bash
node tools/decode-track.mjs      # 交付的 m4a → audio/bgm-mono.wav(22050 Hz mono) + audio/track-info.json
node tools/hit-map.mjs           # 音头 + 音头间隔直方图 → audio/hit-map.json
node tools/timing-map.mjs        # 把拍/小节网格拟合到音头 → audio/timing-map.json
```

没有网格就不要往下走。`sync-storyboard-timings.mjs` 读 `beat.period` / `beat.offset` / `bar.duration` / `duration` 来排每一条字幕；`verify-timing.mjs` 读同一组字段来判你的切点是否合法。

## 1. 为什么必须测量：自相关在这条轨上给出 64.6 BPM，真相是 112.91

本 skill 早期版本里有个 `beat-analyze.mjs`（**已移除**，职能被 `hit-map.mjs` 取代），走的是教科书路线：onset envelope 的自相关 + 相位搜索 + 90–140 BPM 偏好加权（×1.18，75–160 BPM ×1.06）。它在这条轨上给出：

| 字段 | 值 |
|---|---|
| `tempo.bpm` | **64.6**（滞后 80 帧 @ 86.133 fps = **0.9288 s**） |
| `tempo.offsetSec` | 0.8417 |
| `beatCount` | 173 |
| `tempoAlternatives` 第 2 名 | **112.35 BPM，score 0.831 vs 1.329** |

正确答案就在它自己的备选列表里，只是排在错的后面。真正的周期是 **0.5314 s / 112.91 BPM**。

**失败模式。** 这条轨的节拍周期性弱（大量持续音、母带压得很紧），自相关曲面近乎平坦，最高峰落在一个和拍点无关的 lag 上：0.9288 s 既不是拍（0.5314 s），也不是小节（2.1256 s）或半小节（1.0628 s）；0.9288 / 0.5314 = **1.7478**，不是任何整数或半整数倍。单标量 tempo 估计在这种曲面上不可判定，而且它**不会报错**——它只会给你一张自信的、错的网格。

**代价（可以直接算出来，别凭感觉）。** 拿这两张网格分别去对 `hit-map.json` 的 301 个真实音头：

| 网格 | 周期 | 拍数 | 落在音头 ±45 ms 内 | ±15 ms 内 |
|---|---|---|---|---|
| 自相关（64.6 BPM） | 0.9288 s | 173 | 28/173 = **16.2%** | 6/173 = 3.5% |
| 直方图 + 拟合（112.91 BPM） | 0.5314 s | 303 | 204/303 = **67.3%** | 201/303 = 66.3% |

按 64.6 BPM 切镜头，六分之五的切点落在没有声音的地方。它不会让 lint 或 check 报错，只会让整片"感觉不对"——而"感觉不对"无法定位、无法复现、无法验收。

**结论：你要的不是"每分钟多少拍"，是"哪些时刻真的有声音"。**

## 2. 真正干活的方法：音头间隔（IOI）直方图

`tools/hit-map.mjs` 的全部参数与顺序如下，照抄即可。

1. **STFT → 频带能量。** `N = 1024`、`HOP = 128`，在 22050 Hz 下帧率 **172.27 fps（5.8 ms/帧）**。64 个对数等分频带（35 Hz → 12 kHz），带值 = `log1p(sqrt(平均功率) × 200)`。
2. **正向谱通量（ODF）。** 逐带取 `band[t] − band[t−1]` 的**正部**求和；这是 onset detection function，不做任何"哪个乐器"的判断。
3. **轻平滑 + 全局归一。** 3 帧（≈17 ms）滑动平均，然后按全程均值/标准差做 z 归一 → `z[t]`。
4. **自适应阈值峰值拾取。** 局部极大值先过一遍；阈值是**局部**统计量：以 ±21 帧（≈±122 ms）为窗算 `mu`、`lsd`，要求 `z[t] ≥ mu + 1.0 × lsd + 0.25`；再按 `z` 从高到低贪心保留，任意两个音头间距 `≥ MIN_IOI = 0.07 s`。这条轨得到 **714 个音头（4.4 个/秒）**。
5. **IOI 直方图。** 0–2 s、**1 ms bin**；每一对音头 `(i, j)` 投票给 `t_j − t_i`，权重是 `min(z_i, z_j)`（弱音头之间的巧合不算数）；直方图再按 **±12 bin（±12 ms）** 平滑，吸收打击乐起音的时间抖动。候选取 60–1600 ms 的局部极大，35 ms 内去重，前 8 名按最高分归一。

这条轨的直方图峰值（前 6 名，score 已归一）：

| ioi (s) | 隐含 BPM | score | 相对 0.534 s |
|---|---|---|---|
| 0.534 | 112.36 | 1.000 | ×1 |
| 1.596 | 37.59 | 0.974 | ×3 |
| 0.267 | 224.72 | 0.971 | ×0.5 |
| 0.801 | 74.91 | 0.937 | ×1.5 |
| 1.329 | 45.15 | 0.934 | ×2.5 |
| 1.062 | 56.50 | 0.933 | ×2 |
| 0.406 | 147.78 | 0.181 | — |
| 0.133 | 451.13 | 0.180 | — |

**怎么读这张表——这就是"脉冲是真的"的判据。** 前 6 名全部是同一个数的 **0.5/1/1.5/2/2.5/3 倍**，与 0.534 s 的最大偏差 **6 ms**（1.596 与 3×0.534=1.602 差 6 ms；1.062 与 2×0.534=1.068 差 6 ms）。第 7 名开始分数掉到 1/5（0.181、0.180）——真实的脉冲及其倍频与噪声之间有一条**断崖**。如果前几名之间没有整数/半整数关系，或者没有断崖，那多半是伪影，别用它当网格。

两个必须知道的细节：

- 直方图只给"大致周期"（1 ms bin + ±12 ms 平滑），0.534 s 与拟合后的 **0.5314 s** 差 2.6 ms；精修交给下一步，不要在这里凑数。
- `hit-map.json` 另外存一份**精挑过的音头表** `hits[]`：按 `z` 排序后保留间距 ≥ `HIT_MIN_GAP = 0.28 s` 的 **301** 个（`z` 0.13–8.55）。这是"实在没有可用脉冲"时的兜底素材，也是做音效时的落点候选池。

## 3. 精修周期与相位：网格拟合

`tools/timing-map.mjs` 在直方图给出的量级附近做一次二维穷举，判据是"网格点上有多少音头能量"：

- **搜索空间**：`period` 从 **0.50 → 0.56 s，步长 0.00005 s（0.05 ms）**，共 1201 个周期；每个周期再扫 **60 个相位**（步长 `period/60`）。
- **打分**：对每个 `t = offset + k × period` 找 ±45 ms 内最近的音头，取 `z × (1 − d/0.045)` 的最大值（越近越值钱），累加后**除以 √(拍数)**。
- **为什么必须除 √n**：否则周期越短、拍数越多的网格天然累积更多能量，搜索必然滑向搜索区间的上界，你会得到一张"每 0.50 s 一刀"的假网格。

结果：**period 0.5314 s → 112.91 BPM，offset 0.4163 s，303 拍**，`bar = 4 拍 = 2.1256 s`。小数位不是装饰——`sync-storyboard-timings.mjs` 用它把每一帧的开始算到毫秒，`verify-timing.mjs` 用同一组数回判，两处只要有一位不一致，33/33 就会变成 32/33。

```bash
node tools/timing-map.mjs            # -> audio/timing-map.json
```

## 4. 拍号：只有两种假设要判，判据是对比度

网格只给"拍"，不给"小节"。`timing-map.mjs` 用同一张网格分别假设 3 拍和 4 拍，把每个位置上的音头强度求和，看能量有多集中在某一格：

```
contrast = (max(sums) − mean(其余位置)) / mean(全部位置)
```

这条轨实测：

| 假设 | 各位置强度和 | contrast | topIndex |
|---|---|---|---|
| 3 拍 | 281.4 / 284.4 / 288.3 | **0.019** | 2 |
| 4 拍 | 223.9 / 172.9 / 148.1 / 309.3 | **0.598** | 3 |

0.598 vs 0.019 的差距就是判决：**4/4**。score 高者胜（`meter = contrast4 ≥ contrast3 ? 4 : 3`）。

`topIndex` 是免费的附加信息，但要读懂它：它说重音落在循环里的**哪一格**。这次是 **3**，也就是 `bars[]` 发出的每条小节线落在最重那拍**之后一拍**。`timing-map.mjs` 只用 contrast 选 `m`，**不会**顺手把 bar 相位搬到 `topIndex`——这次也没搬，33 个切点照样全部落在 bar 线上并通过验收。如果你确实想"bar 线 = 重音拍"，公式是 `newOffset = offset + topIndex × period` 再重建 `bars[]`，但改完必须重跑 `verify-timing.mjs`：切点、字幕、音效全部会跟着移动。

## 5. 置信度：网格是真的还是编的

`gridFit` 就是回答这个问题的两个数：

| 字段 | 值 | 含义 |
|---|---|---|
| `matchedBeats` / `totalBeats` | **204 / 303** | 有多少拍附近（≤50 ms）真的存在一个音头 |
| `medianAbsErrMs` | **2.3 ms** | 命中那些拍的中位绝对误差 |

`beats[].hit` 为 `null` 表示最近音头在 50 ms 之外；**先看 `hit` 是否为 `null` 再看 `errMs`**——`errMs` 永远有值（就是到最近音头的距离），这条轨里存在 269.7 ms 这种数字，误读成"误差 270 ms"会得出完全相反的结论。

补充一个自查：303 拍里有 201 拍落在音头 ±15 ms 内，而命中的有 204 拍——也就是说命中一旦成立，误差几乎都在验收容差（15 ms）以内。

**这个数不好时怎么办（按顺序试，别跳步）：**

1. **降峰选门槛**：把 `mu + 1.0 * lsd + 0.25` 里的 `1.0` 调到 `0.5`（甚至去掉 `+0.25`），重跑 `hit-map.mjs` → `timing-map.mjs`。音头更多，`matchedBeats` 会上升，但 `medianAbsErrMs` 也会变差——两个数一起看。
2. **放宽拟合窗**：把 ±45 ms 放到 ±60–70 ms（同时改 `gridScore` 与 `beats[]` 的 0.05 判定），适用于现场感强、起音发散的录音。
3. **承认它没有可用脉冲**：如果怎么调都过不了 15 ms 断言，就不要造网格。回到 `hit-map.json` 的 `hits[]`（这条轨 301 个音头）做**纯音头剪辑**：切点和重音都吸到最近的音头上，字幕靠读速闸门约束。假的网格比没有网格更糟——它会让后面每一个脚本、每一帧都在一个不存在的节拍上对齐。

## 6. 读结构：把曲式变成文本

`timing-map.mjs` 的意义不只是输出网格，而是把结构打印成人能读的几行：

- **乐句**：`bar = 2.1256 s` → 4 小节 8.502 s、**8 小节乐句 = 17.005 s**。选切点时优先落在 4 小节线上，其次 8 小节线（乐句线），这是"这一段讲完了"的听觉信号。
- **响度弧**：`arc[]` 是 2.5 s 桶的 `avg`/`peak`（0–1），打印成 64 字符 sparkline，字符集 `' ▁▂▃▄▅▆▇█'`；另有 `energy peaks by 10 s region`，用 `█ × round(avg × 40)` 画柱。
- **音头密度**：`density[]` 是每 4 s 的音头数（hits/s），同样打印成 sparkline，并每 20 s 标一个数值。
- **段落变化**：`hit-map.mjs` 用 0.5 s 块的频带 novelty（前后各 4 块的均值差）找峰值，阈值取全程最大值的 0.22，间隔至少 3.5 s，得到 `sections[]`。

**这条轨的真实读数（很能说明问题）：**

- 响度弧**几乎是平的**：10 s 区块的 `avg` 全程在 0.81–0.91，只在最后 1 s 掉到 0.26。母带压得太紧，响度在这里**不能**当结构线索用。
- 密度才有形状：0.5–2.25 hits/s，60–70 s 与 140–150 s 两个 2.25 的峰，100–110 s 掉到 1.5。
- `sections` 14 个：11 / 17 / 30 / 34 / 60 / 77 / 87.5 / 91.5 / 106.5 / 110.5 / 136.5 / 140.5 / 153.5 / 158.5，`strength` 最大的是结尾 1.000，其次 17 的 0.577、77 的 0.373。

**别把 `sections` 当切点表**：它的块粒度是 0.5 s。实测里 60 / 77 / 136.5 / 153.5 落在 8 小节乐句线（59.93 / 76.94 / 136.45 / 153.46）的 ±70 ms 内，11 / 17 / 34 / 87.5 / 110.5 / 140.5 / 158.5 落在某条小节线前 ≤0.45 s。用法是：**它告诉你"音乐在这里换气质了"，切点仍然吸到最近的小节线**。

把这几行文本抄进 STORYBOARD 的 TIMING BIBLE 注释块（成片就是这么做的），这样"为什么这一段是 8 小节"在文件里看得见，不需要重新听一遍。

## 7. 输出契约

后面的脚本按 key 读，不要改名、不要改单位。

`audio/hit-map.json`（`hit-map.mjs`）：

```jsonc
{
  "source": "audio/bgm-mono.wav",
  "duration": 161.017,                       // 秒
  "resolution": { "odfFps": 172.27, "odfStepMs": 5.8 },
  "pulse": {
    "candidates": [ { "ioi": 0.534, "bpm": 112.36, "score": 1 } ],  // score 已按第 1 名归一
    "note": "IOI histogram peaks; weak metrical periodicity — prefer hit-locked timing"
  },
  "onsetCount": 714,                         // 峰选后的音头总数
  "hits":  [ { "t": 0.406, "z": 4.03 } ],    // 间距 ≥0.28 s 的精挑音头，t 秒 / z 强度
  "sections": [ { "t": 11, "strength": 0.332 } ],
  "energy": [ { "t": 0, "e": 381.532, "rel": 0.829 } ]   // 10 Hz，rel 为 0..1
}
```

`audio/timing-map.json`（`timing-map.mjs`）：

```jsonc
{
  "duration": 161.017,
  "beat": { "period": 0.5314, "bpm": 112.91, "offset": 0.4163, "count": 303 },
  "meter": 4,
  "bar": { "beats": 4, "duration": 2.1256, "count": 76 },
  "beats": [ { "i": 0, "t": 0.4163, "hit": 0.406, "errMs": -10.3, "strength": 4.03 } ],
  "bars":  [ { "i": 0, "t": 0.416, "end": 2.542 } ],
  "gridFit": { "matchedBeats": 204, "totalBeats": 303, "medianAbsErrMs": 2.3,
               "meter3": { "m": 3, "sums": [281.4, 284.4, 288.3], "contrast": 0.019, "topIndex": 2 },
               "meter4": { "m": 4, "sums": [223.9, 172.9, 148.1, 309.3], "contrast": 0.598, "topIndex": 3 } },
  "arc":     [ { "t": 0, "avg": 0.838, "peak": 0.932 } ],       // 2.5 s 桶
  "density": [ { "t": 0, "hitsPerSec": 1.75 } ],                // 4 s 桶
  "energy":  [ /* 同 hit-map.json，原样带过来 */ ]
}
```

约定：

- **时间一律是"全片绝对秒"**，从音频第 0 秒算起；不存在帧号或帧内时间。
- `bars[k].t = offset + k × bar.duration`，`beats[n].t = offset + n × beat.period`；后面的脚本用它反推每一帧、每一条 cue 的位置，你手写的任何时间都会被覆盖或判错。
- `beats[].hit` 可能是 `null`（该拍附近 50 ms 无音头），这是正常值，不是缺数据。
- `bar.count = 76`，最后一条小节（`bars[75]`，起点 159.836）的 `end = 161.962` 已经越过 `duration`；使用时要按 `duration` 截断（成片最后一帧就是这么做的）。

## 8. 诚实边界

这套方法在成片上跑通了，但它能回答的问题很窄。以下都是它**做不到**的：

- **不认下拍、不认乐器。** `meter` 只给"3 拍还是 4 拍"和能量对比度，`topIndex` 只说"重音在第几格"。它不会告诉你那是不是底鼓、哪一拍是正拍。想要"底鼓/军鼓/踩镲"级别的判断，需要分频带各自建 ODF，这套脚本没有做。
- **不处理变速与段落级漂移。** 全片假设**一个** `period` + **一个** `offset`。这条轨 112.91 BPM 恒定，所以成立；如果曲子中途变速，从变速点往后每一拍都会漂，而且 `medianAbsErrMs` 只会略微变差——它不会明确告诉你"后半段错了"。遇到变速，正确做法是分段各自跑一次，得到多组 `{period, offset, 起止时间}`，再让下游按段取网格。
- **在 rubato / 自由速度 / 重压缩素材上很弱。** 本片恰好就是重压缩素材：自相关直接失败（§1），响度弧也失去形状（§6）。IOI 直方图能撑住，是因为它只看音头**之间**的间隔，不看振幅包络。
- **脉冲可能真的不存在。** 环境音、drone、纯氛围铺底没有可用的节拍。这时不要伪造网格——按 §5 第 3 条退到纯音头剪辑。验收侧的 15 ms 断言会立刻告诉你哪个选择是对的。
- **音头表本身有取舍。** `HIT_MIN_GAP = 0.28 s` 会吃掉靠得很近的装饰音（这条轨的 IOI 表里 0.267 s 是第 3 名，说明确实存在十六分级的间隔）；`MIN_IOI = 0.07 s` 又决定了什么算"两个音头"。如果你的片子需要 0.15 s 级别的密集落点，调这两个数，然后重跑整个下游。
- **`sections[]` 是提示，不是结论。** 0.5 s 块 + 0.22 相对阈值，只保证"这里有个变化"，不保证是编曲意义上的段落边界。用它做交叉印证，不要用它当剪辑决策。
