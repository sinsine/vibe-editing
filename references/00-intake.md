# 00 · 接单：把一段主题收成一份可执行的 brief

> 这是整套技能的前门。你的产物是**一份已确认的 `BRIEF.md`**（骨架 `templates/BRIEF.md`，字段语义见
> `brief-format.md`），不是立刻开写画面。项目根目录已有 `BRIEF.md` 时，它就是"不要再问一遍"的令牌：
> 读它，别重新盘问；发现它记的是别的工作流名，是走错了房间，交给那个工作流。

## 1. 用户定什么，方法定什么

对用户只有一句承诺：**主题你定，方法固定。**

**固定的（不要拿去问用户，也不要在中途自己发明）：**

| 环节 | 固定做法 |
| --- | --- |
| 量音乐 | 先量后写：`scripts/hit-map.mjs` + `scripts/timing-map.mjs` 出脉冲候选、真实音头、能量包络、段落边界 → `audio/hit-map.json`、`audio/timing-map.json` |
| 推导网格 | `scripts/timing-map.mjs` 把拍/小节网格拟合到音头上，并对比 3/4 与 4/4 → `audio/timing-map.json` |
| 切点 | 场景边界只落在**小节线**（bar line）；动画重音与字幕 cue 落在**拍线**（beat line） |
| 注入时间 | 帧只写 `bars`；`start/end/duration/cues` 由 `scripts/sync-storyboard-timings.mjs` 注入，永不手写 |
| 音效与混音 | `scripts/build-sfx-map.mjs` / `scripts/mix-soundtrack.mjs`，逐条记录来源与许可 |
| 校验 | `scripts/verify-timing.mjs`（切点在小节线、cue 与音效在拍线，容差 15 ms，并对渲染出的音效轨做声学复核）· `scripts/verify-frames.mjs`（跨文件静默故障）· `scripts/audit-still.mjs`（亮度、字幕带、对比）· `scripts/audit-covers.mjs`（封面） |
| 交付 | 渲染成片 MP4（内嵌字幕、混音母带）+ 发布物料，格式见 `templates/PUBLISH.md` |

**可变的，只有这七项**：主题、受众、时长/音乐、语言、语气（与禁忌）、投放平台、是否要旁白。
用户的自由在内容侧；"要不要卡点""字幕放哪""用什么渲染"不是问题，是方法的结论。

## 2. 接单问题：只问缺的，一次最多五个

问到能写 `## Intent` 为止。每一问都带"为什么要问"，用户才知道该答什么颗粒度。

| 问题 | 为什么必须问 | 用户没答时 |
| --- | --- | --- |
| 主题 + 一句话主张 | `message` 是片子的唯一真值，后面每一帧的"为什么"都要追回它 | 按 §4 提案两三个角度让用户挑，不要自己定 |
| 受众，以及他们已经知道什么 | 决定起点：从他们正在经历的处境开口，还是从术语开口 | 从平台推断，并在提案里写明假设 |
| 音乐 | 用户给文件 / 从素材库选 / 生成 —— 三种走法影响后续全部时间轴 | 默认素材库按 `message` 情绪取，并把 BGM 写进 `## Assets` |
| 目标时长，或"用满整首" | 时长决定帧数上限与呼吸节奏；"用满整首"是合法答案 | 默认 60–90 s |
| 有无旁白 | **无旁白则字幕即声音**，这决定整套排版：双层排版、中央大字承担重音、底部字幕保留带 | 默认无旁白 |
| 投放平台 | 决定封面比例（B站 1146×717、抖音主页网格 3:4）与文案口吻 | 默认横版 + B站 |
| 语气与禁忌 | 语气决定用词，禁忌比语气更重要（不说什么、不主张什么） | 提案里写好语气，让用户在闸门一里改 |

三条规矩：

1. **brief 已经回答的，不要再问。** 已经给了 `message` 就不要问"你想表达什么"。
2. **一次最多五个问题。** 挤牙膏式追问会让用户以为你在拖；剩下的用合理缺省 + 提案补。
3. 用户答"随便"时，给两三个**具体选项**让他指，而不是继续追问。

## 3. 两个只能由人拍板的闸门

方法负责正确，人负责判断。这两个闸门不是流程礼貌，是**品味唯一的入口**。

### 闸门一 · 内容稿审核（画面开工之前）

把逐帧计划当**提案**交出来，用 `story-spine.md` §3 的表形：

| Frame | Beat | On screen | Why |
| --- | --- | --- | --- |
| 01 — 有个问题 | hook · 6.4s | 把观众的处境问成一个待回答的问题 | 主张在第一拍落地 |

开口先复述策略句：**"This video tells [受众] that [主张]。"**（用中文说也一样。）
人在这里判断的是**话与结构**：主张是不是他想说的、顺序对不对、有没有该删的帧、长度是否可接受。
`Why` 追不回主张的帧，是删掉的帧，不是要装饰的帧。每帧改一次这里花 30 秒，建完再改花几分钟。

**交出提案后停下，等答复。** 不要"一边等一边先把第 1 帧搭起来" —— 那等于把闸门变成通知。

### 闸门二 · 画面审核（渲染之前）

把已建成帧的**静帧**交出来：`hyperframes snapshot` 导出的 PNG，逐帧过一遍。
人在这里判断的是**画面**：构图、字体层级、颜色语域、遮挡、重音落在哪一拍、这一格好不好看。
`scripts/audit-still.mjs` 会同时给出机器侧的量（有没有真的被点亮、字幕带里有没有墨、有没有内容贴在左上角、
高光有没有爆），但那些是筛子，不是判决。

### 脚本查不了美

校验脚本能断言：切点在不在小节线、cue 在不在拍线、字幕带有没有被侵占、对比度够不够、有没有非确定性调用。
校验脚本查不了：这个比喻成不成立、大字压在麦穗上难不难看、第 12 帧的情绪是不是过头。
**所以美只从这两个闸门进来。** 不要用"脚本全绿"代替过人眼，也不要在闸门之前就开始建画面。

## 4. brief 很薄的时候

用户只给了主题（甚至只有一句话），你的动作是**要主张，不要剧本** —— 写剧本不是用户的工作。
不要静默替他选一个角度然后跑完。

- 提 **2–3 个不同主张**的角度，每个写清：主张原句、为什么它对这个受众成立、需要什么证据支撑。
- 让用户挑一个，或让他改一句 —— 通常他会直接给出一句更好的。
- 挑定之后再回到 §2 的缺项补问（音乐、时长、平台），不要在第一轮就把七个问题全倒出去。

一个反例：用户说"讲讲拖延症"。不要直接开写"拖延症的三个原因"（那是原文顺序的产物），
而是给出「拖延不是懒，是情绪调节失败」/「你不是没时间，是不敢开始」/「截止日期是最便宜的生产力工具」
三条不同主张，让用户选一条。

## 5. 一个真实例子

用户的一段话（下面这段是按真实 brief 里已确认的字段复原的写法，不是逐字原话）：

> 做个《苏格拉底的麦穗》的视频吧，讲最优停止的，给高中生和大学生看。我不想要旁白，就用我给的这首
> BGM 铺满整首，卡点。发 B站和抖音。

解析结果：

| 项 | 值 | 落点 |
| --- | --- | --- |
| 主题 | 苏格拉底的麦穗与最优停止 | `## Intent` |
| 主张（`message`） | 你无法知道哪支麦穗最大，但你可以决定什么时候停下来 | frontmatter |
| 受众 | 高中生与大学生 | frontmatter |
| 时长 / 音乐 | 用满整首 BGM，161 s（`We Never` 2:41.08） | `length` + `## Assets` |
| 旁白 | 无 —— 字幕即声音，双层排版（中央大字 + 底部小字） | `## Intent` + `## Customizations` |
| 平台 | B站 + 抖音 | `destination` + 发布物料 |
| 语气 | 克制、清醒、偶尔温柔幽默；像大几届的学长，不像老师 | `## Intent` |

七问里这段话答了六问，**只剩"语气与禁忌"没答** —— 这正是闸门一之前必须补的那一问。
frontmatter 里没有"语气""禁忌"这两个键，它们落在 `## Intent`（语气）与 `## Notes`（禁忌）：
不说"这个故事是柏拉图写的"、不主张期望值版本的最优解、不要第三条彩色。补问晚了的代价是文案整体写偏，
而它们改写不进 frontmatter，只能进正文。

关于 `destination`：它是单值。真实 BRIEF 记的是 `youtube`，而发布物料是 B站 + 抖音 ——
多平台分发时 `destination` 记主平台，其余平台写进正文与发布物料，别指望一个字段装下三个平台。

## 6. 交付契约：用户最后拿到什么

1. **成片 MP4** —— 内嵌字幕轨、混音母带，分辨率与帧率写在 `## Customizations` 里。
2. **封面（多比例）** —— 至少 16:9、B站 1146×717、3:4（抖音主页网格）。
3. **标题与简介（按平台）** —— 每个平台一条推荐 + 备选，附标签/分区与发布建议。
4. **校验报告** —— 卡点、帧文件、静帧、封面四项断言的机器可读结果。

第 3、4 项的产出格式与交付前检查清单见 `references/09-publish.md`；封面尺寸与平台上限也在那里，
不要凭印象写数字。写回：中途任何被确认的决定（换时长、加一个平台、接受某个定制）都当场写进 `BRIEF.md` ——
只活在对话里的决定，恢复会话时不存在。
